# AI Worker — оцінка ризиків (2026-11-22)

Об'єкт: Cloudflare Worker `lexi-ai` (`tools/ai-worker.js`; копія `docs/integration-3.0/ai-worker.lexi-proposed.js` однакова). Production-версію не змінювали й не розгортали. Навантажувальних тестів production не було.

Позначки: **CONFIRMED** — перевірено тестом або запитом; **INFERRED** — висновок з коду; **NOT VERIFIED** — перевірити неможливо без доступу.

## 3. Рекомендації (нічого не застосовано)

1. **W8, W1 — спершу:** перевірити ліміт витрат у консолі Anthropic (це найдешевший і найсильніший захист). Потім додати загальний денний ліміт на всі запити (KV або Durable Object), наприклад 3000 відповідей / день, з 503 після досягнення.
2. **W3:** брати dev-origin зі змінної середовища (`DEV_ORIGIN`), у production не задавати.
3. **W2, W4:** Firebase App Check або Cloudflare Turnstile — **спершу в режимі моніторингу**, enforcement лише після перевірки на Android / TWA. Автоматично не вмикати.
4. **W5:** після релізу стежити за `AI_USAGE` у логах Cloudflare тиждень; бюджети не підвищувати без дозволу.
5. **W7:** обмежити веб-ключ Firebase referrer-ами `lerenbe.com/*` і пакетом `be.leren.app`.
6. Сайт (не Worker): HSTS зараз `max-age=86400` (1 день) — рекомендовано 1 рік (`31536000`); `style-src 'unsafe-inline'` у CSP лишається через вбудовані стилі (P3).

## 4. Вердикт

Блокуючих ризиків для релізу 264 немає. W1 + W8 — найважливіша дія власника незалежно від релізу. W6 закривається живим тестом перед злиттям.
