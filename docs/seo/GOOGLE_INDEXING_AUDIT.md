# Аудит індексації lerenbe.com в Google (2026-11-25)

Доповнює `docs/seo/SEO-AUDIT-2026-11.md` (22.11). База — `main` після релізу 264 (`1312d86`), live-сайт перевірено 25.11.2026. Лише читання production; усі зміни — у цій гілці.

> Проходження технічних SEO-тестів **не гарантує** індексацію чи позиції. Остаточна перевірка — Google Search Console і наступний обхід Google.

## 1. Executive summary

- **Блокувань індексації (P0) не знайдено.** Усі 4 URL із sitemap відповідають 200, `robots.txt` дозволяє обхід, `noindex` немає на жодній сторінці sitemap, canonical збігаються з URL sitemap, домен має DNS TXT `google-site-verification` (схоже на підключений Search Console — підтвердить лише власник).
- Імовірні причини, чому сайт погано знаходять: новий домен, мало зовнішніх посилань, застосунок-SPA з одним URL і малою кількістю статичного тексту, дві публічні сторінки LIFE без внутрішніх посилань, без Open Graph і з поганими сніпетами.
- У гілці виправлено: внутрішні посилання на LIFE, description для `privacy.html`, Open Graph/Twitter для 3 сторінок, статичний h1 для сторінки історій, `lastmod` головної, новий тест `tests/seo-pages.cjs`.
- Вердикт: **CONDITIONAL GO** — зміни безпечні, але ефект видно лише після обходу Google; потрібні дії власника в Search Console.

## 2. Підтверджені технічні факти (CONFIRMED)

| Факт | Доказ |

| `html lang="uk"`, hreflang відсутній (правильно: мови — на одному URL) | `index.html` |
| Cloudflare перед GitHub Pages; TLS Let's Encrypt (до 17.01.2027) | openssl, заголовки |

## 3. Непідтверджені гіпотези (потребують Search Console / вимірювань)

1. Головна може бути в статусі «Виявлено / Просканована, але не проіндексована» через малу кількість контенту до JS.
2. Google може не бачити контент застосунку, якщо рендеринг відкладається через вагу JS.
3. Cloudflare Bot Fight Mode / WAF може блокувати справжній Googlebot за IP (за UA — не блокує).
4. LCP/CLS/INP на мобільному — не виміряні (PageSpeed API без ключа дав 429, Lighthouse локально немає). Реальних даних CrUX немає.
5. Позиції за брендовими, помилковими й тематичними запитами не перевірялись: прямої видачі Google інструмент не має, `WebSearch` — не Google SERP. Позицій не вигадую.

## 8. Залишкові ризики

- Невидимість до обходу Google; без Search Console стан індексації невідомий.
- Один URL для всіх мов і SPA — мало статичного тексту.
- Два `<h1>` на відрендереній головній (дрібна SEO-вада).
- Вага JS, короткий HSTS, `favicon.ico` 404.
- Тести не повні: 3 падіння на `main`, браузерні набори пропущені.

## 9. Дії власника в Google Search Console

1. Відкрити property `lerenbe.com` (Domain, ймовірно підтверджений DNS TXT).
2. **Індексація → Сторінки:** чи є головна і 3 інші сторінки; причини виключення.
3. **Sitemaps:** подати `https://lerenbe.com/sitemap.xml`, перевірити «Успішно», 4 URL.
4. **Перевірка URL → Перевірити живий URL** для `/`, `/learn-life.html`, `/learn-life-story.html`, `/privacy.html`; переглянути «Відрендерений HTML» (чи видно контент застосунку); натиснути «Запит на індексацію» після релізу.
5. `/reviews.html` має бути «Виключено тегом noindex» — це правильно.
6. **Статистика сканування** (Налаштування): чи заходить Googlebot і з якими кодами.
7. **Основні вебпоказники** (мобільні) і **Покращення** (структуровані дані).
8. У Cloudflare: Security → Events — чи немає блокувань Googlebot; Bots/WAF; за бажанням HSTS `max-age=31536000`.
9. Надіслати результати розробнику — без них цифр Search Console не вигадуємо.

Тексти потрібні від власника.
4. Окремі мовні лендінги `/en/`, `/fr/` із hreflang — лише за рішенням власника.
5. Рішення про `/guides/` (зараз `noindex`).
6. Зовнішні посилання: українські спільноти й канали в Бельгії, каталоги.
7. Вимірювання продуктивності (Lighthouse, PageSpeed із ключем, CrUX) і окреме завдання з ваги JS.
